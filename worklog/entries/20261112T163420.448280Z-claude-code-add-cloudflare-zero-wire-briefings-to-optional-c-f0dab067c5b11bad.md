# Add Cloudflare Zero Wire briefings to optional context

## Summary

The user approved adding Cloudflare Radar's Zero Wire vulnerability briefings as a source. It is a curated, low-volume feed (8 briefings at implementation time) whose public RSS carries stable slugs, update dates, a `Needs attention`/`Reference` label and exact CVE IDs as `<category>` tags. It was added as a third optional `check --context` source, not as applicability evidence: briefings are `state: review` leads matched locally only when an exact CVE tag equals a CVE referenced by an existing finding. Topic tags (`Node.js`, `Kernel`, `PHP`) are not matched to packages because they are product labels, not package identities. Briefing prose, including upgrade versions and mitigation steps, is dropped before caching. The HTML page returns 403 to automated clients; the RSS endpoint returned 200.

## Changes

- `netwatch/sources.py`: fixed `ZERO_WIRE` RSS endpoint (GET only, 5 MiB, 10 s socket/20 s elapsed limits, returned as text); `zero_wire_catalog` rejects DOCTYPE/ENTITY declarations, validates slug/guid/link/date/tag identities and keeps only identity, title, dates, priority, CVE references and topic tags; `zero_wire_context` matches exact CVE overlap; `context()` caches `zero-wire` and records `report.context.zero_wire` with retained-on-failure semantics shared with other sources.
- `netwatch/cli.py`: `--context` help text and a labeled Zero Wire section showing source priority, update date and matched CVEs.
- `tests/test_context.py`: synthetic RSS fixtures; opt-in, caching/refresh, failure retention, skipped/cleared context, lookup-limit, display and transport tests extended; new parsing tests for CVE-only matching, prose dropping and malformed/entity/duplicate/foreign-link/naive-date feeds.
- `README.md`, `docs/USAGE.md`, `docs/DESIGN.md`, `docs/DELIVERY.md`: source table, matching/coverage limits, CC BY-NC note (Radar API terms; feed terms unstated), JSON path and limits.
