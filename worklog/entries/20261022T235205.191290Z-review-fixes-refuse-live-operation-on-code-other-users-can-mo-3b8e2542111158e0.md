# Refuse live operation on code other users can modify

## Summary

The review found that the README installs into a user-owned `.venv` in the checkout, and the OPERATIONS live template ran `python3 -m autoprotect` as root. That puts the current directory first on `sys.path`. Also, `_PROBE` is whatever file sits beside the installed package. Live mode checked policy and state ownership but never the code root would execute, so a non-root user could get code run as root.

Outcome: before any `--live` command reads policy or state, the CLI requires root-only control of the `autoprotect` package (recursively, including the APT helper and bytecode caches) and of every existing `sys.path` directory or importable file, including ancestors. Otherwise it fails with a `policy_error`. The docs now prescribe a root-owned `/opt/autoprotect` environment for live use.

## Changes

- `autoprotect/local_files.py`: `require_trusted_code(package_dir, search_path, *, owner=0)` using the existing descriptor-relative protected traversal. It rejects group/world-writable or non-root entries, symlinks and non-regular files; an empty path entry means the current directory.
- `autoprotect/cli.py`: `_operate` calls it for `--live` after the effective-root check, before loading policy or preparing state.
- Tests: `tests/test_local_files.py` (`TrustedCodeTests`), `tests/test_cli.py` (live refusal from this user-owned checkout before policy/state access; live dispatch passes the package directory and `sys.path`).
- Docs: `README.md` (user venv is non-live only), `docs/OPERATIONS.md` (root-owned installation section; live templates use `/opt/autoprotect/bin/autoprotect`), `docs/DESIGN.md` (check contract).

## Validation

- `python3 -m unittest discover -s tests`: OK. `python3 -W error::ResourceWarning -m unittest discover -s tests -k test_local_files`: OK.
- Disposable `debian:trixie-slim` container with `python3-minimal` (3.13.5) installed inside it: every default `sys.path` directory is `root:root 0755`. A root-owned copy of the package at `/opt/ap` was accepted; a uid-1000-owned copy was rejected ("protected path ancestors must be owned by root or the invoking user").
- `git diff --check`: clean.
- Not tested: the installed `/opt/autoprotect` entry point running an actual live command.
