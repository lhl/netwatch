# Replace oversized runtime with small multi-environment CLI

## Summary

The user rejected the oversized implementation and explicitly requested a clean, minimal Python/SQLite replacement, actual Ubuntu/Arch/CachyOS/conda/mamba/uv/npm environments, light function-level extensibility and no subagents. Replaced the runtime rather than extending its framework. Application code is 905 lines including the demo and retained version comparator, down from 5,433. This deliberately changes the product's trust/action contract: a human approves an environment-wide package-manager update, not an exact-artifact transaction. No automatic privileged policy service is retained.

## Changes

- `adapters.py`: explicit environment registry validation, ordinary local/quoted SSH commands, installed inventories, update discovery and fixed whole-environment commands for all seven kinds. No generic plugin framework.
- `sources.py`: Canonical Noble USN evidence, conservative Arch tracker matching and OSV exact-version PyPI/npm queries. Conda-native coverage and CachyOS rebuild applicability stay unknown. Cache only Noble matching fields rather than historical artifact data.
- `store.py`, `workflow.py`, `cli.py`: private SQLite schema 10, source cache, inventories, first/last-seen findings, cursor events, queryable errors, preview/approval/apply/recollection, failed-update holds and manual recovery notes. Failed checks preserve earlier information; apply cannot silently replay an interrupted attempt. Existing state schemas are rejected and preserved, not migrated or deleted.
- Removed the old executor, policy/approval framework, probe, source pipeline, obsolete tests/fixtures/examples and sprawling active documentation. Retained `versions.py`, its tests, and worklog tooling/tests/history. Updated project version to 0.2.0 and simplified README, DESIGN, DELIVERY and AGENTS.
- Self-review found and fixed false clean results on malformed/empty source data, lost observations during failures, duplicate refresh downloads across targets, unknown Arch statuses treated as affected, and reuse of previews across recovery. Fixed commands never consume advisory installation text or feed-selected versions.
- Explicit limitations: broad update approval permits changing repository candidates; package scripts have operator authority; runtime/service remediation is not proven; projects and database are trusted; alias duplicates and other administrators are not centrally coordinated. Interrupted remote work must be inspected before recovery. No independent review or subagent work was performed, per user instruction.

## Validation

- `python3 -B -m unittest discover -s tests -v`: 47 tests passed, covering 23 replacement workflow/adapter/source tests, 4 retained version-comparison tests and 20 worklog tests. All command/network behavior in the deterministic suite is injected; every adapter's inventory/update/apply command scope is exercised.
- `python3 -B -m autoprotect --json demo`: affected package, denied apply without approval, approved simulated update, package-state recollection, no remaining synthetic finding, and 12 recorded events. Temporary state cleaned up; no network or native updates.
- `python3 -B scripts/check_package.py`: offline wheel/source build, isolated install, console/module entry points and installed demo passed.
- README registration examples executed via ordinary CLI against disposable SQLite: seven environments registered and cached status queried without connections. Local Markdown links checked.
- Separate bounded public-source smoke: exact OSV query for the public Jinja2 2.11.2 fixture returned 10 advisories; Arch endpoint returned 2,446 records; Canonical export yielded 1,614 Noble notices and a 7,049,941-byte compact JSON cache. These observations are source-contract checks, not completeness or deployment guarantees. No private inventory was queried or transmitted.
- Worklog checks/render and `git diff --check` passed. New entry is checked in the staged index before commit. Git/history and previous committed worklog entries are retained.
- No actual system was inventoried or updated. No services, credentials or remote hosts were changed; no push or deployment. Native package-manager versions, SSH credentials, lifecycle scripts and restart/reboot procedures still require qualification on explicitly authorized targets.
