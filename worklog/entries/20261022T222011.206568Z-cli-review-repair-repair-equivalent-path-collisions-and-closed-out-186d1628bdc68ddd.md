## Changes

- Changed only `autoprotect/cli.py`, `tests/test_cli.py`, and this new entry. `autoprotect/__main__.py` needed no change. Parent-owned native reservations, the original 42 CLI tests, and all other worker changes remain present. No staging or commits were performed.
- Added a comparison-only path key that collapses leading slash spellings after lexical absolute normalization. Linux treats `/tmp` and `//tmp` as the same location; `os.path.abspath` alone preserves their different spelling. Both simulator/database destinations and the parent's independently located native coordination destinations now use the same key as policy/import paths. Original paths still go to protected readers and database preparation, so comparison never erases an unchecked symlink, missing directory, non-directory or unsafe ancestor before actual traversal.
- Added both-direction `/` versus `//` regressions: actual temporary Simulator/Engine recovery with a valid policy at the gate-publication alias; simulator inventory/feed imports at that alias; and all four native reserved names across policy/inventory/feed inputs using only a temporary mocked native directory. Rejected inputs remain byte-for-byte intact. Explicit original-ancestor tests cover both slash spellings, invalid components before `..`, and successful valid parent traversal.
- Routed JSON output, error output and argparse help/version through one explicit write-and-flush boundary. A failed write/flush produces the fixed JSON `io_error` with exit 1 on usable stderr. If the failed stream is the interpreter's original stdout or stderr object, it is closed while suppressing its flush exception; Python's text wrapper closes its buffer even when that flush fails. Shutdown therefore cannot retry buffered output and replace the requested exit with 120. No `os._exit`, process termination shortcut, global stream replacement, descriptor redirection or skipped Store cleanup is used.
- Caller-provided capture/embedded streams are not closed or replaced. Their failures still produce bounded CLI results, but their later lifecycle remains caller-owned. If stderr itself is unavailable, its diagnostic cannot be delivered; the original error exit is retained and nothing is written to stdout as a fallback. Successful help/version remain plain text, while their output failures use JSON on stderr like other output failures. The command matrix, live/provenance rules and normal success/error/recovery exits are unchanged.
