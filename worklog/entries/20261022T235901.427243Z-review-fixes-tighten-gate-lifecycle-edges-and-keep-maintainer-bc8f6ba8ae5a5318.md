# Tighten gate lifecycle edges and keep maintainer-script services

## Summary

The review raised four low-severity lifecycle/runner issues:

1. `execute()` publishes the gate before recording the claim. If recording failed, the gate stayed on a plan that was not `executing`, and only `resolve-recovery` (not `recover`) could clear it.
2. `resolve-recovery --malformed-digest` could mark any unrelated unfinished plan `needs_attention`.
3. The runner waited for pipe EOF, so a descendant holding stdout turned a finished command into a deadline timeout. It also SIGKILLed the whole process group after success, including services started by `dpkg` maintainer scripts.
4. The stable-suite freshness behavior was undocumented (addressed in the native-compatibility entry).

Outcome:

- A claim-recording failure before commit withdraws the just-published gate via the new backend `cancel()`, allowed only under the same lock and before `apply` was entered.
- `recover` handles a retained gate on a pending/approved plan: such a claim never committed, so mutation never started. It finalizes the plan `failed`, commits, rotates the generation and clears the gate.
- Malformed-gate resolution finalizes the named plan only if it is `executing`.
- After the command exits, the runner waits at most one second for pipe-holding descendants. `keep_descendants=True`, used only by `dpkg --install`, leaves them running after a normal exit; failures still kill the group.

## Changes

- `autoprotect/backends.py`: `_Gated.cancel()` and an `_applying` flag (set by `_require_execution`, reset per lock); `dpkg --install` passes `keep_descendants=True`.
- `autoprotect/engine.py`: the `execute` claim withdraws the gate if `store.claim` raises. `recover` keeps the executing path in one transaction and adds the unclaimed path (outcome commit, then `clear_gate`, a generation-rotation check and a `recovery-gate-cleared` event). Malformed resolution finalizes only `executing` plans. Unused `FINAL_STATUSES` import removed.
- `autoprotect/runner.py`: `_PIPE_GRACE`, the `keep_descendants` parameter (validated boolean) and `_CommandProcess.stop(kill=...)`.
- Tests: `tests/test_engine.py` (claim-failure cancel for sqlite and KeyboardInterrupt, unclaimed recover with generation rotation, malformed resolution of executing vs approved plans, synthetic `cancel`), `tests/test_runtime_pipeline.py`, `tests/test_backends.py` (real simulator cancel rules; the fake runner asserts `keep_descendants` only for install), `tests/test_runner.py` (daemon holding pipes is bounded and killed or kept; failures kill even when keeping).
- Docs: `docs/DESIGN.md` (backend protocol `cancel`, lifecycle, malformed scope, runner contract) and `docs/OPERATIONS.md` (recover semantics, evidence table, runner descendants).
