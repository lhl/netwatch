# Repair armored APT keys and preserve all release constraints

## Summary

Repair the two independently reproduced APT probe defects without removing supported Signed-By formats or changing public repository targets. Armored keys now undergo bounded, isolated conversion before signature verification. Every distinct contributing Release constraint survives resolution, even when several repository paths share the same exact origin tuple. The focused probe suite passes all 39 tests; parent integration and independent review remain required.

Only the assigned probe, probe tests, two public-only synthetic fixtures and this entry were changed. No staging, commit, shared documentation edit, agent launch, host inventory, APT/dpkg command, repository download, package/service operation or live configuration change was performed.

## Changes

- `autoprotect/_apt_probe.py`: `_verify_release` gives both signature verification and optional armor conversion a private mode-0700 temporary directory under `/tmp`, an explicit home directory, a controlled working directory and a minimal environment. Binary `.gpg` Signed-By files go directly to `/usr/bin/gpgv`; this path does not invoke or require `/usr/bin/gpg`.
- Armored `.asc` Signed-By files are read through the existing protected reader with a 4 MiB cap, copied into a mode-0600 temporary input, and converted with fixed `/usr/bin/gpg --no-options --homedir ... --batch --no-tty --no-autostart --no-default-keyring --no-auto-key-retrieve --no-auto-key-import --output ... --dearmor ...` arguments. Conversion does not import keys, consult user configuration/keyrings, start an agent or retrieve remote keys. The conversion child receives a 4 MiB file-size limit, respecting a lower inherited hard limit; the parent limit is unchanged. Conversion and verification each retain a 30-second subprocess timeout and discard tool output. Missing tools, conversion failure, empty/oversized output and signature failure cannot authorize an index. Temporary state is removed after success and normal exception/interruption unwinding.
- **Operator prerequisite for parent documentation:** `/usr/bin/gpg` is additionally required only when a configured Signed-By key is armored `.asc`. `/usr/bin/gpgv` remains required for both formats. Private scratch space under `/tmp` is required. No Python dependency was added. The resource-limit callback is used only in the single-threaded isolated probe process; this is not a general multithreaded subprocess API. Forced process death can leave temporary files; normal cleanup is not a crash-containment claim.
- `_resolve` maintains separate origin and release-constraint collections. `target.origins` remains the sorted list of unique exact `{origin, label, archive, codename, component, site}` tuples. Internal `evidence.releases` contains sorted exact `{origin, codename, date, valid_until}` records, with `origin` holding the full corresponding target-origin tuple. Only exact duplicate constraints deduplicate. More than 1,024 distinct constraints fail resolution rather than truncating evidence. Public target fields are unchanged. The backend consumer was not edited; it must validate every constraint and enforce exact target-origin coverage.
- `tests/test_apt_probe.py`: retains the original 27 cases and adds 12 cases for isolated conversion arguments/environment, byte/time/file-size bounds, no-gpg binary operation, missing executable, conversion failure, timeout, interruption, partial-output cleanup, empty/oversized/missing output, failed verification, real binary/armored signatures, invalid armor, altered signed content, unrelated keys and ignored synthetic user trust/configuration. Release regressions cover old/future dates, expired/different validity bounds in either order, cross-origin coverage, exact-duplicate deduplication, and the 1,024/1,025 boundary. Both `.list` and deb822 `.sources` retain `.asc` parsing support.
- `tests/fixtures/apt-probe/archive-public.asc` and `tests/fixtures/apt-probe/InRelease`: public-only offline fixtures. A temporary RSA-2048 key was generated and used for signing through `/usr/bin/openssl`; Python encoded the OpenPGP packets and armor. Only the public key and synthetic signed Release remain. No private key is stored in the repository, no external signing service was used, and fixture generation did not invoke a GPG agent. Tests decode the public armor with Python for the independent binary control; they do not generate keys or require OpenSSL. The Release's package checksum is synthetic and matched by the fake index-hash interface, not evidence of a real repository.
