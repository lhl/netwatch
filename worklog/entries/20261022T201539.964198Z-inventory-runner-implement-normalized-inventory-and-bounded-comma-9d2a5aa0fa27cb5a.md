# Implement normalized inventory and bounded command runner

## Summary

Implemented the assigned normalized inventory import, read-only local dpkg collector, and shared bounded command runner. Imports cannot establish native provenance from a body label. All collection tests use synthetic identity data and fake dpkg runners; no development-host inventory or package mutation was performed. Changes are handed to the parent without staging or committing.

## Changes

- `autoprotect/inventory.py`: `normalize_inventory(data, collector="imported")`, `inventory_fingerprint(inventory)`, and `collect_local(runner=None)`. Normalize strict booleans/timestamps, reject duplicate package identities, and sort by ecosystem/name/architecture. The fingerprint excludes only `observed_at` from already normalized records.
- Debian packages use ecosystem `deb`, as coordinated with the parent. They require explicit source name/version in imports; missing source fields reject the whole import with a request to supply source metadata. Invalid Debian names/versions also reject the whole import rather than dropping a package. Other ecosystem labels remain unsupported, retain bounded printable ASCII names/versions, and use binary identity only when source fields are absent. Explicit null/empty source values are rejected in every ecosystem. Platform/architecture labels use the shared ASCII identifier validator.
- Native collection uses only `/usr/bin/dpkg --print-architecture` and two identical `/usr/bin/dpkg-query --show` calls with fixed Package/Version/Architecture/source:Package/source:Version/Status fields. It never runs installed application binaries, APT, scripts, or package mutation commands. Two normalized observations must agree; this detects observed drift but is not a substitute for an execution-time package-manager lock.
- Parse bounded `/etc/os-release`, falling back only on absence to `/usr/lib/os-release`, without shell expansion or merging. Read and SHA-256 hash `/etc/machine-id`; reject missing/uninitialized/malformed identity. Native virtual source fields retain separate source versions and their documented missing-field fallback. Held, partial, desired-removal and reinstreq states remain visible. Missing required package versions fail collection rather than inventing safe state.
- Collector test injection is the existing `runner` argument plus patched `autoprotect.inventory._read_file(path, limit)` and `now()`. There is no alternate filesystem root or command configuration exposed to CLI/import data. Raw identity files are capped at 64 KiB for os-release and 4 KiB for machine ID; query output at 16 MiB, inventory count at 100,000 packages.
- `autoprotect/runner.py`: immutable `CommandResult(returncode, stdout, stderr)` and `Runner.run(argv, *, timeout=60, cwd=None)`. Absolute executables, argument arrays, closed stdin, `shell=False`, a minimal non-inherited environment, default cwd `/`, concurrent bounded stdout/stderr reads, fixed elapsed deadlines, process-group SIGKILL cleanup, and bounded reaping. Nonzero exit codes return normally; spawn failure is `BackendError`, and started-command deadline/output/I/O failures are `IndeterminateError`.
- Runner constructor addition: `Runner(max_output_bytes=16*1024*1024)`, with limits of 1 byte through 64 MiB. Timeouts must be finite and above zero through 3600 seconds; cleanup waits at most one additional second. Output is decoded as UTF-8 with replacement. Argument count, individual length, total encoded size and cwd length are bounded.
- Runner integration addition: `with runner.dpkg_frontend_lock():` acquires the fixed existing `/var/lib/dpkg/lock-frontend` with nonblocking POSIX record locking and supplies `DPKG_FRONTEND_LOCKED=true` only to that runner in the owning process/thread. Tests patch only the private path constant to temporary synthetic files. The backend must enter this context instead of independently opening/closing the frontend inode, must separately require authorized root execution, and must add the database lock for recovery. Nested/same-process competing contexts, external contention, unsafe files and changed inodes are rejected. There is no arbitrary environment override.
- `tests/test_inventory.py` and `tests/test_runner.py`: synthetic import/native fixtures, hostile and malformed input, source/binary-rebuild mapping, source-label spoofing, bounds, drift, real subprocess output/deadline cleanup and synthetic POSIX lock contention. No separate fixture files were needed.
