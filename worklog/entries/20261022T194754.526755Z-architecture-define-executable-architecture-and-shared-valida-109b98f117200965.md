# Define executable architecture and shared validation contracts

## Summary

Defined the implementation contract for the requested security-advisory-to-remediation proof of concept, preserving all original deliverables. The initial native target is Debian 13/trixie amd64, with a disposable simulator and explicit manual/automatic execution paths. Added shared, tested validation helpers before parallel runtime assignments. No implementation or production-readiness claim is made for the proposed runtime modules.

## Changes

- Added `docs/DESIGN.md`: requirements, scope, threat model, source provenance, normalized schemas, Debian matching, policy and immutable approval binding, durable execution/recovery gates, package-manager locking, audit, deployment, advisory-only harness integration and module contracts.
- Added `autoprotect/core.py`, `autoprotect/__init__.py` and `tests/test_core.py`: bounded strict JSON, canonical hashes, identifiers, text/integer and Debian-version syntax validation, plus shared exception semantics. Control-bearing prose stays data and canonical output escapes it.
- Split the broad implementation task into source/inventory/matching, backend, persistent lifecycle and CLI integration work packages. `docs/DELIVERY.md` remains the overall checklist; no unfinished implementation requirement was removed.
- Independent `astra-xhigh` design review found four valid gaps. Corrected the contract to account for dpkg replacement/removal effects and full package-state deltas, retain target-wide uncertainty across plans/databases, bind repository codenames/configuration/freshness, and define installed lineage as an explicit operator trust assumption rather than inferred provenance.
- Clarified a reloadable policy provider and a pre-mutation authorization callback; imported content cannot self-assert HTTPS/native acquisition.

## Validation

- `python3 -m unittest discover -s tests -p 'test_core.py' -v`: 7 tests passed. Tests were written alongside the shared helpers; coverage includes duplicate keys, oversized/deep/malformed JSON, non-finite numbers, lone surrogates, canonical identity, escaped terminal controls, strict integers, command-like identifiers and version syntax.
- `python3 -m unittest discover -s tests -v`: the final candidate passed 28 tests, including 8 shared-helper tests and all 20 existing worklog tests.
- Design local-link, code-fence and whitespace checks passed; `git diff --check` passed. The implementation status table explicitly keeps proposed runtime and fleet behavior pending.
- `/usr/bin/docker version --format '{{.Server.Version}}'` returned Docker daemon version 29.9.1. This establishes disposable-container availability, not any successful Debian integration or privileged operation.
- Independent design follow-up accepted all four fixes at contract level, subject to one exact ordering clarification. Added that clarification: write/fsync the target gate under lock before committing `executing`; retain an orphan gate for recovery even if claim commit did not occur. Runtime review and native lock integration tests remain required.
- A separate `astra-xhigh` helper review found that `IndeterminateError` inheriting from the pre-mutation `BackendError` contradicted their contracts. Made them sibling subclasses of `AutoprotectError` and added an executed regression test proving the uncertain exception cannot be caught as pre-mutation failure. No other concrete helper findings were reported. The parent verified the corrected inheritance and the final 28-test suite.
- Marked the six design checklist items complete; all application implementation and final integrated-review requirements remain open. `python3 scripts/worklog.py check` passed with three valid indexed entries; `git diff --staged --check` passed. Reviewed all six staged paths and their complete diff.
