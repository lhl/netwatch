## Changes

- Gate publication serializes the complete record before creating files, writes and fsyncs a private preparation file, then publishes through an exclusive `os.link` that cannot overwrite an existing destination. It removes the temporary alias and fsyncs the containing directory before `begin` succeeds. A per-lock successful-begin marker prevents `apply` after a caught interruption or failed durability check, including a second begin attempt under the same lock.
- The temporary publication alias is a reserved hidden name derived from the destination filename. Readers accept a two-link publication state only when the second link is exactly that alias and has the same device/inode. Unknown hardlinks remain rejected. Recovery removes the known alias before removing the gate; an interrupted alias cleanup therefore remains recoverable. A bounded unpublished preparation file can be discarded only under the target lock when no published gate exists. No directory scan or lease is used.
- Simulator initialization and opening reject hidden filenames and names ending in `.lock`, `.gate` or `.generation`, before writes. This reserves the current coordination and temporary namespaces. A legacy JSON simulator body stored at a lock filename cannot be opened as another simulator and cannot replace an active lock inode. Parent validation-before-normalization and protected descriptor traversal remain in place.
- Added `generation() -> str` to both backends. The durable record is `{generation: TOKEN}` in the existing target namespace: adjacent `STATE.generation` for simulation, fixed `/var/lib/autoprotect/targets/local.generation` for native execution. Missing records return 64 zeroes. Native reads do not create state directories, locks or generation records, and still reject unsafe ancestors and unsafe/malformed generation files.
- `clear_gate(plan_id, resolution, *, malformed_digest=None)` validates gate evidence before any generation change. A valid gate requires the exact plan ID and no malformed override. A bounded malformed private regular gate requires an explicitly matching raw SHA-256 digest; that attestation is not proof of prior-plan identity. Missing/wrong gates and stale overrides change neither the generation nor gate. Every accepted explicit resolution creates a new random 64-hex generation, atomically writes and flushes it, then removes and flushes the gate. Normal succeeded/failed `finish` does not rotate the generation. A failed or interrupted generation write retains the gate.
- Recovery locks now yield null, `{plan_id: ID}`, or `{malformed: true, digest: RAW_SHA256}`. Invalid JSON, duplicate keys, invalid plan IDs and zero-byte regular gates are bounded malformed evidence. Gate reads are capped at 4,096 bytes; generation records at 256 bytes. Symlinks, FIFOs, directories, unknown hardlinks, nonprivate files, oversized objects and observed concurrent changes fail closed with bounded diagnostics. Normal lock entry still rejects every retained gate.
- Native release evidence now requires exact `{origin, codename, date, valid_until}` records, with 1–1,024 records. Each origin must exactly match a target origin; every target origin must be covered. All records are checked without positional pairing or collapsing constraints that share an origin. Public repository-target fields are unchanged. The backend retains immutable date/expiry tuples and the validated maximum age from final preparation. Immediately after `before_mutation`, it checks current time against those constraints before invoking dpkg, without another probe, hash, inventory collection or simulation pass. Expiry at this boundary is a confirmed pre-mutation BackendError.
- Tests add abrupt process-exit injections at twelve publication stages and six recovery-generation/removal stages, graceful KeyboardInterrupt and fsync failures, exact no-overwrite publication, two-link recovery, reserved-name collision prevention, native read-only generation behavior, cross-instance generation visibility, malformed digest attestation, unsafe filesystem objects, release coverage/bounds and post-callback expiry/age/clock-reversal checks. Existing frontend handoff, artifact, transaction, policy, path, locking, interruption and success tests remain active.
