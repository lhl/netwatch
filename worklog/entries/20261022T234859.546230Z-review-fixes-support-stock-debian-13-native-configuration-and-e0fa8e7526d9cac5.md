# Support stock Debian 13 native configuration and review bootstrap

## Summary

The review found that the native backend could not run on any stock Debian 13 host. Inspecting the local `debian:trixie-slim` image (offline, disposable) showed:

- `_fingerprint_tree` rejected every symlink, but base-files ships `/etc/dpkg/origins/default -> debian` and debian-archive-keyring ships `*.gpg -> *.pgp` aliases in `/usr/share/keyrings`;
- the default `Signed-By` uses `.pgp`, which the source parser rejected;
- the default mirrors are plain HTTP;
- readiness rejected any removed-but-configured (`rc`) or multiarch package anywhere on the host;
- the package pinned Python `<3.13` while trixie ships 3.13;
- there was no reviewed way to obtain `approved_config_digest`;
- stable-suite freshness behavior (no Valid-Until; Date changes only at point releases, six weeks old on 2026-10-23) was undocumented and its denial was opaque.

Decisions:
- Accept HTTP sources. Integrity already comes from per-source InRelease signatures, Packages hashes and the exact artifact hash; transport is not the authority.
- Follow root-owned symlinks only when they resolve inside the checked roots. Record link text in the digest; the target is fingerprinted as an ordinary entry.
- Provide a read-only `native-config` observation labelled `approved: false`, never an automatic approval.

## Changes

- `autoprotect/_apt_probe.py`: `_OWNER`, `_safe_link`, `_resolve_key`, `KEYRING_DIRECTORIES`; `_fingerprint_tree` records in-root links (including directory links) and rejects escaping, dangling or non-root links. Source parsing accepts `http` (port 80) and `https` (port 443), `.pgp` keys, skips `deb-src` and `Enabled: no` stanzas, and rejects malformed types and enabled flags. dpkg config accepts absolute `path-exclude`/`path-include`. Refactored `_signed_release`/`_origin`/`_checked_config`, and added a `config` action that runs `_config_report`.
- `autoprotect/backends.py`: `_ready` accepts settled dpkg states and foreign architectures, but not unfinished dpkg work. `_package` requires a fully installed `amd64`/`all` target. `_check_release_times` names the failed bound. New `DebianApt.configuration_report()` validates the probe output shape.
- `autoprotect/cli.py`: `native-config` command (no global options, never live).
- `pyproject.toml`: `requires-python = ">=3.12"`. `scripts/check_package.py` accepts 3.12+.
- Tests: `tests/test_apt_probe.py` (stock trixie sources, HTTP ports, real-filesystem symlink and key-alias cases, dpkg path filters, config report), `tests/test_backends.py` (rc/multiarch acceptance, unfinished-state rejection, target state, report validation), `tests/test_cli.py` (native-config).
- Docs: `docs/DESIGN.md` and `docs/OPERATIONS.md` (native prerequisites, review procedure with `native-config`, stable-suite freshness guidance), `README.md` (Python requirement, native-config).
