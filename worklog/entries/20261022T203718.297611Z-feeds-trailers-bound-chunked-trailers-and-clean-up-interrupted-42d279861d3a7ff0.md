# Bound chunked trailers and clean up interrupted fetch startup

## Summary

Repaired the independently reproduced task-5 HTTP chunked trailer gap and the parent's adjacent successful-start interruption finding. Chunked responses remain supported, including bounded benign trailers. Malformed, incomplete, oversized or metadata-changing trailers fail the fetch without returning partial data. Cleanup now inspects the worker's actual state instead of a flag assigned after `start()`.

This entry supplements `worklog/entries/20261022T201354.208028Z-feeds-implement-bounded-pwn-and-debian-feed-adapters-d57c04c0ad51c237.md`. Its original tests did not cover the standard library's permissive trailer reader or interruption between successful worker startup and the caller's flag assignment. Both gaps now have red-first regressions. The final assigned feed suite passed 36 tests. No staging or commits were performed.

## Changes

- `autoprotect/feeds.py`: installed an instance-local validator at the real `HTTPResponse._read_and_discard_trailer` hook. The standard library still decodes chunk bodies. The trailer section permits at most 100 distinct fields and 32,768 wire bytes, including field delimiters and its final CRLF empty line. Each `readline` is limited to the remaining byte budget plus one detection byte; trailer values are never accumulated or merged into response metadata.
- Trailer validation rejects EOF before the final empty line, bare-LF endings, partial lines, folded fields, malformed names, ASCII control bytes including ESC and DEL, duplicate names and names already present in initial headers. It rejects framing, content interpretation, routing, authentication, cache/control and validator fields, including ETag. Connection-nominated fields are also forbidden. An optional `Trailer` declaration must contain distinct valid permitted names; when present, actual trailers must be among them. Duplicate `Trailer` and `Connection` header lines are rejected rather than overwritten.
- Bounded benign fields, including informational digest text, are discarded without verification or authority. They cannot replace ETag/content headers, change the endpoint or supply acquisition provenance. The public parse/fetch signatures and result dictionaries are unchanged. The existing 8 MiB/128 MiB body caps, 10-second socket cap and 60-second parent worker deadline remain; trailer reads also check the cumulative deadline individually.
- `autoprotect/feeds.py`: removed the `started` flag. Cleanup calls `Process.is_alive()`, which is also valid before startup, and terminates a live child even when `start()` successfully spawned it before an interruption reached the caller. Cleanup retains at most two 0.25-second joins, escalates to kill if needed and never closes a process still reported alive.
- `tests/test_feeds.py`: added synthetic wire streams using the actual standard-library `HTTPResponse`, not a fake decoder. Regressions cover accepted empty/benign trailer sections, 100/101 fields, the 32 KiB byte boundary, more than 62 KiB of fields, a 256 KiB unterminated line, every ASCII control byte, incomplete framing, forbidden/ambiguous metadata, cumulative deadline checks, public worker success/failure and stalled trailers. Startup regressions use a real spawned synthetic worker plus a fake persistent-live worker to verify interruption propagation, cleanup escalation and bounded joins. The real-process test includes its own cleanup for the red-first failure.
