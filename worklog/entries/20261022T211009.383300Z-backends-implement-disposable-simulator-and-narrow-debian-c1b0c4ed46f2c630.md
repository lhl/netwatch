# Implement disposable simulator and narrow Debian APT backend

## Summary

Implement task 6's complete remediation backend protocol without running live patching or editing parallel lifecycle/CLI work. Added a disposable state-changing Simulator and a narrow DebianApt implementation with offline verification. Both retain a durable target gate for unresolved execution; native operations use the runner's frontend-lock handoff and require an additional database lock for recovery. Imports and simulation do not require python3-apt.

This is a completed backend implementation unit, not integrated product acceptance or a claim of privileged runtime verification. All package state, repository evidence and artifacts used in tests are synthetic. No host inventory, native package command, package installation, repository refresh, service operation or configuration change was performed. No staging or commit was performed by this worker.

## Changes

- `autoprotect/backends.py`: implements `Simulator(path)` and `DebianApt(runner=None, *, live=False)` with the exact documented `name`, `inspect`, `resolve`, `lock`, `begin`, `finish`, `clear_gate` and `apply(..., before_mutation=...)` protocol. Repository targets retain the complete documented schema; no engine contract change is required. `lock` additionally yields the retained `{plan_id}` gate or null for callers that need recovery evidence.
- `Simulator.initialize(path, inventory, catalog, *, failure_mode=None)` exclusively creates a private JSON file and returns a Simulator. Catalog entries are complete target dictionaries; initialization forces `collector=simulator`. `set_failure(mode)` changes only the test control under the target lock. Modes are null, `before_write` and `after_write`. Atomic writes update the selected binary/source versions and observation time, leaving unrelated package fields unchanged. Synthetic hashes are never download claims.
- Simulator state requires an existing private nonsymlink parent directory. Its lock and gate are adjacent to the state file. Native state uses fixed `/var/lib/autoprotect/targets/local.lock` and `local.gate`, independent of asset aliases and SQLite paths. Both use stable nonblocking flock locks, exclusive gate creation, file and directory fsync, exact plan-ID checks, and explicit recovery resolution. Newly created native state directory entries are also flushed in their parents. `finish` clears a gate only for `succeeded` or confirmed `failed`; Engine must call it only after its outcome transaction commits durably. Other outcomes and interruptions retain the gate.
- Native lock entry requires live opt-in and root, then holds `runner.dpkg_frontend_lock()` across inventory, candidate/transaction validation, preparation, installation and verification. It never independently opens the frontend inode. Recovery also acquires a nonblocking POSIX record lock on `/var/lib/dpkg/lock`; partially configured package state does not by itself prevent recovery. No downgrade or arbitrary rollback operation exists.
- `autoprotect/_apt_probe.py`: an isolated `/usr/bin/python3 -I` helper imports distribution `apt`, `apt_pkg` and `apt_inst` only when invoked. It reads local APT candidate policy, validates every same-version record, rejects ambiguous artifacts, and preserves source/binary versions separately. It verifies candidate InRelease signatures with fixed `/usr/bin/gpgv` arguments and hashes the actual decompressed Packages index through fixed `/usr/lib/apt/apt-helper cat-file` arguments. Signed Release origin/codename fields must agree with APT's cached origin. Native backend policy additionally checks exact approved origins, configuration/keyring digest, release date, optional expiry, and maximum metadata age.
- Configuration fingerprinting covers `/etc/apt`, `/etc/dpkg` and `/usr/share/keyrings`; metadata fingerprinting covers the fixed APT lists directory, excluding locks, partial downloads and auxiliary cache files. Protected regular files/directories are required. The supported source subset is explicit HTTPS binary sources with Signed-By key files under `/usr/share/keyrings` or `/etc/apt/keyrings`, trixie/trixie-updates/trixie-security, and amd64 indexes. Both `.list` and deb822 `.sources` are parsed. Trust/date overrides, external config includes, redirected trusted inputs, executable/solver overrides and unsafe dpkg options are rejected. The supported dpkg configuration subset is comments, `no-debsig` and `log /var/log/dpkg.log`.
- Native execution rejects imported/wrong-host/wrong-platform inventories, incomplete or non-ready state, held targets, essential/protected candidates, sensitive package/source families, source mismatch and non-increasing binary versions. A fixed pinned `apt-get --simulate --assume-yes --no-remove --only-upgrade --no-install-recommends install -- NAME:ARCH=VERSION` must report only the planned upgrade and configuration. Candidate and artifact Conflicts/Breaks/Replaces are independently rejected.
- Download uses `Version.fetch_binary(..., allow_unauthenticated=False)` after exact candidate/configuration/metadata revalidation, into a fresh private staging directory. Artifact size is capped at 256 MiB; the helper sets RLIMIT_FSIZE to the approved size and supplies a bounded acquisition progress check. Backend validation requires one private regular `package.deb`, exact byte count/SHA-256, binary/source identity, architecture, and acceptable control fields. Control inspection never extracts payloads or runs scripts. Download preparation has a 300-second runner deadline; metadata probes and simulations use 120 seconds, and installation uses 900 seconds. Runner startup and process-containment limitations still apply.
- After preparation, the backend rechecks complete inventory and candidate/transaction equality, then calls `before_mutation()` immediately before fixed `/usr/bin/dpkg --force-confdef --force-confold --install PRIVATE_ARTIFACT`. This uses the default conffile answer and preserves local conffiles when no default is available. Native apply independently compares the complete observed inventory to the expected singleton delta; Engine must still perform its own check. Nonzero installation, failed verification, uncertain startup and post-invocation exceptions are indeterminate; KeyboardInterrupt propagates with the gate retained. Confirmed preparation rejection remains BackendError. Staging cleanup never masks the installation outcome.
- `tests/test_backends.py` and `tests/test_apt_probe.py`: offline coverage for authorized manual/auto simulation, fake native success, exact argument arrays, hashes/sizes/identities, trust/configuration/signature/index checks, freshness, transaction and relationship rejection, locks/gates across instances/processes, durable directory creation, callback timing, interruption, failures and recovery. One test uses the real Runner frontend context against a temporary synthetic lock file, verifies DPKG_FRONTEND_LOCKED handoff, and asserts that the inode is opened exactly once. No native command is spawned.
