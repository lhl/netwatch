# Repair final authorization and target recovery binding

## Summary

Repair three independently reproduced lifecycle findings while preserving authorized manual and automatic execution: authorization could expire or be revoked during the final expensive validation pass; clearing an uncertain execution gate did not invalidate previously approved work in other databases; and resolving the wrong gate finalized an unrelated plan before the backend rejected it. Implement the coordinated recovery-generation and malformed-gate extension from `docs/DESIGN.md`.

This entry corrects the corresponding completeness claims in `worklog/entries/20261022T210715.505213Z-lifecycle-implement-persistent-policy-approval-and-executi-8237353a8d02dbc7.md`. That earlier entry remains unchanged. This is an implementation/focused-test handoff for parent integration and original-reviewer re-review, not final milestone closure.

## Changes

- Changed only `autoprotect/engine.py`, `autoprotect/store.py`, `tests/test_engine.py`, `tests/test_store.py`, and this new entry. Backend/probe code, parent integration tests, shared documents, and earlier worklog entries were not changed. No staging or commit was performed.
- Added a bounded final authorization check after all inventory/source hashing, target validation, and applicability matching. It reloads the small collection/generation and source-health records, reloads and validates the bounded policy document, then reads the clock last. Scalar comparisons recheck plan expiry, approval expiry, source freshness, inventory-head freshness, and the independently collected preflight observation. It does not load/hash source or inventory bodies or run matching again. The callback's last expensive validation pass ends with this check; planning and approval also use it.
- Store schema version is now **2**. Existing version-1 databases fail clearly without migration or deletion. `inventory_heads` adds nullable `backend` and `target_generation` columns; both must be present together for collection authority. `Store.save_inventory(body, *, backend=None, target_generation=None)` validates the pair, and `Store.inventory_context(asset_id)` reads it without reloading the large inventory body. Public inventory envelopes remain `{id, body}`.
- Actual backend collection reads `generation()` before and after observation, rejecting an observation spanning a rotation. Imported data never supplies this context and clears any prior collection context for its head. Identical same-second collection can retain its immutable inventory content ID while replacing the head's generation; no timestamp inference is used.
- Immutable plans now bind `target_generation`. Planning, approval, and execution require the current backend and generation to match the collection context; execution also requires the plan's generation. Old plans remain invalid even after a fresh collection. After explicit resolution, both manual and automatic paths require actual new collection and a new plan; manual mode requires a new bound approval. Outcome observations also record their backend/generation context.
- Recovery uses the evidence yielded by `backend.lock(asset_id, recovery=True)`. A normal gate must identify the exact requested plan and cannot accept an override. Missing/wrong evidence is rejected before any outcome or status change. `recover` applies the same check before marking abandoned execution `needs_attention`.
- Added `Engine.recovery_status(plan_id)`, returning `{plan_id, asset_id, status, gate, generation, prior_plan_identity_verified}` without changing outcomes or audit rows. `gate` is the exact validated contract shape: null, `{plan_id}`, or `{malformed: true, digest}`.
- Extended `Engine.resolve_recovery(plan_id, actor, reason, *, malformed_digest=None)`. Bounded malformed evidence requires the explicit matching raw digest; stale/missing digests and any override of a valid gate are rejected. Audit records retain the gate evidence and distinguish operator attestation from verified prior-plan identity. The result preserves `status`, `gate_cleared`, and `verified=False`, and includes the gate evidence, identity-verification flag, and new `target_generation`.
- Resolution commits the attestation before calling the backend's coordinated `clear_gate(..., malformed_digest=...)`, then checks that the backend's generation changed and records completion. Generation rotation/publication durability belongs to the backend implementation; this layer never fabricates a rotation. A failure before the attestation transaction commits rolls back status/outcome changes and leaves the gate and generation untouched. An uncertain commit also prevents this call from proceeding to gate clearing.
- Extended only the disposable synthetic test backend with generation persistence, recovery-lock evidence, and exact malformed clearing. It rotates the persisted token before removing its temporary-state gate. It does not import or invoke the actual backend implementation.
