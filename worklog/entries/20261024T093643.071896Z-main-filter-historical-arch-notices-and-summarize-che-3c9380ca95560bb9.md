# Filter historical Arch notices and summarize check output

## Summary

The user requested fixes after an authorized local CachyOS check produced excessive name-only historical notices and raw JSON-like terminal output. Added native version filtering and a bounded readable report. Updates were not applied. Machine inventories and package versions remain in private local state, outside Git.

## Changes

- `adapters.py`: validate version strings and run the target's `vercmp` in batches of up to 64 unique pairs. Versions are positional arguments to a fixed script; they never become shell source. Remote targets use the existing quoted SSH runner.
- `sources.py`: omit notices whose fixed version is at or below the installed repository-package version. Keep foreign packages, missing/malformed fixes and remaining CachyOS applicability uncertain. Missing/failed comparison reports an incomplete check and preserves prior findings. Record the omission count with source evidence; filtering is version-based, not verification of rebuilt package contents.
- `cli.py`: summarize affected/review groups, observation times, update versions, pending attempts and failures. Default limits are five package groups per finding category and ten updates. `--all` expands text rows; `--json` retains all records. Escape untrusted terminal text and identify missing fix evidence.
- `store.py`/`workflow.py`: record matching revision and one reassessment event referencing the prior scan when the new rules remove findings. Failed checks do not advance the matching revision. Existing scans/history remain unchanged and no removal is presented as an executed update.
- Added synthetic regression tests and concise README/usage/delivery updates. No subagents, new dependencies or schema migration.
